ChatPD AI Agent 服务优化 — 三种方案

目标：让 AI agent 能高效地查数据集、查论文、查 paper-dataset 网络关系

A

轻量增强：丰富现有 API 响应

不新增端点，在现有 API 响应中嵌入更多上下文。

Pros

  • 改动最小，风险低
  • AI 一次调用拿到更多信息，减少往返
  • 向下兼容

Cons

  • 网络关系查询仍需多次调用
  • 响应体变大

具体改动：每个响应加 _ai_context 字段 — 包含相关数据集、时间趋势摘要、top 共现论文等。

B

新增专用端点 + 图查询

加 3-4 个为 AI agent 设计的端点，支持 paper-dataset 网络关系查询。

Pros

  • 网络查询一次搞定
  • 职责清晰，不影响现有 API
  • 可逐步扩展

Cons

  • 需要新增后端代码
  • 需要设计好 API 语义

新端点：/api/dataset/{name}/related、/api/paper/{id}/co-usage、/api/overview

C

MCP Server + 结构化工具调用

把 ChatPD 包装成 MCP server，让 Claude/其他 agent 通过 tool-calling 直接访问。

Pros

  • 最 AI-Native 的方式
  • Claude 等可直接用 MCP 调用
  • 工具语义清晰，agent 自主组合查询

Cons

  • 需要额外运行 MCP server
  • 非 MCP 的 agent 仍需 REST API
  • 开发量最大

工具：search_datasets、get_dataset_detail、get_paper_datasets、find_related_datasets、get_trends
